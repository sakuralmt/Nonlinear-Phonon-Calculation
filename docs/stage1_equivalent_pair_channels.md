# Stage1 前置的等价声子对通道

从本版起，Prophet、先进 MLFF 和 QE 的 v3 Stage1 都在 `mode_pairs.selected.json` 中写入 `equivalent_pair_channels`。它与模式对使用同一结构、q 网格和归一化契约，因此下游不必各自重新推断等价关系。历史 v3 模式文件保持只读；排序脚本在没有该字段时，按同一规则即时重建，不改写旧文件或既有 Stage2 结果。

前置构建先沿用六方体系的有限 q 等价类：6×6 网格的 35 个有限 q 点归为 6 个代表 q 点。每个代表 q 点保留全部有限 q 分支；每个分支与 Γ 的声学三维子空间、以及按默认 0.01 THz 邻近阈值分组的光学子空间形成通道。通道记录代表 q、原始 q 成员、Γ 分支组及所有成员模式对码。所有 486 个 Γ–q–(−q) 模式对必须恰好出现一次；缺失或重复立即报错。目标材料实际原子排布必须具有所用六方点群，单有六方晶胞度量不足以证明这一点。该元数据未推断其他 q 成员上的单支分支映射。

Stage2 的 `Φ₁₂₂` 完成后，排序脚本直接按通道成员计算 Γ 子空间向量范数 `sqrt(sum_i Φᵢqq²)`，并将被选通道完整展开为后续精算模式对。**近简并组不能只算任意一个分量**：换基会改变单分量，却不改变完整向量的范数。因此这个前置整理不会把一次完整的 486 对 Stage2 势能面评估自动减少为 270 对。它减少的是重复构建通道的工作，并让后续 top-K 精算只处理选中通道的全部成员。不同结构的 Γ 邻近组数可变，物理通道数并不固定为 270。

Stage1 元数据的 `gamma_degeneracy_threshold_thz` 是默认分组定义。排序脚本会复算并逐字段核对前置通道、结构哈希和完整 Stage2 排名；通道成员损坏、不同模式基或不完整排名会拒绝。显式指定另一阈值时，会在同一 486 对结果上重新建立通道并在选样元数据中记录阈值，无需重复计算 Stage2 能量。不同阈值的选样结果应保存在不同文件中。

验证：1/2/3 原子解析覆盖测试与全套仓库测试通过；对既有 Prophet-Phonopy 的 MoS₂、WSe₂ 共用结构及自行弛豫结构四条线，以保存的 486 对 MatterSim 排名离线复算，前置通道与按相同阈值即时建立的通道选样一致。默认 0.01 THz 下四条线均为 270 个通道。早期 0.1 THz 分组会把自行弛豫 WSe₂ 的 Γ6/7（约 7.084 THz）与 Γ8（约 7.177 THz）误并成一组，使该线只剩 216 个通道；这更像偶然邻近而非必须共同处理的对称简并。历史文件不改写，使用显式阈值可复算历史选样。本次没有启动新的 MLFF 或 QE 作业。
